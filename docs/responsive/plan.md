# 반응형 개선 계획

분석 기준: `master`의 `2eefdda`, Astro 5 정적 사이트. `AGENTS.md`의 Jekyll 구조/명령은 현재 저장소에 없으므로 `package.json` 및 `.github/workflows/astro-preview.yml`의 Astro 빌드로 검증한다.

## 실제 페이지/소스 구조

| 화면 | 라우트 | 주요 소스 |
| --- | --- | --- |
| 홈/전체 목록 | `/`, `/page/2/` | `src/pages/index.astro`, `src/pages/page/[page].astro` |
| 카테고리/페이지 목록 | `/category/<path>/`, `/category/<path>/page/2/` | `src/pages/category/[...slug]/**` |
| 글 상세 | `/<post.id>.html/` | `src/pages/[...slug].astro`, `src/styles/post.css` |
| 공통 | 모든 화면 | `BaseLayout`, `SiteHeader`, `SearchModal`, `global.css` |
| 탐색/본문 | 목록/상세 | `CategoryNav`, `PostCard`, `Pagination`, `PostToc` |

실제 콘텐츠는 `src/content/posts`에서 로드된다. `_pages`는 현재 렌더링 소스가 아니다. 기존 URL, 콘텐츠, 분석 및 댓글 설정은 유지한다.

## 분석 및 구현 순서

1. **공통 크기/줄바꿈**: grid/flex 자식의 최소 크기를 해제하고 긴 제목·메타·태그에 줄바꿈을 적용한다. 원래 홈과 2페이지의 목록 CSS가 중복되어 있어 전역 공통 규칙으로 통합한다.
2. **목록**: PC(981px 이상)는 카테고리 사이드바, 태블릿/모바일(980px 이하)은 가로 스크롤 카테고리. 원본 375/768px에서는 카테고리만 약 500px로 글 목록 시작점이 각각 700/649px이다. 태블릿의 이미지/글 병렬 카드는 유지하고 600px 이하에서 세로로 전환한다.
3. **글 상세**: 원본 MySQL 글을 375px에서 열면 문서 폭이 810px까지 늘어난다. 코드·표의 스크롤을 해당 요소 안으로 제한하고 이미지 비율과 목록 들여쓰기를 보정한다. 1180px 이하에서는 본문 앞에 접이식 목차, 1181px 이상에서는 기존 sticky 사이드 목차를 사용한다. JS가 없어도 목차 링크는 사용 가능하다.
4. **검색/터치**: 헤더·테마·페이지 번호에 44px 터치 영역을 확보한다. 검색은 명시적 닫기 버튼, 16px 입력 글자, 동적 뷰포트 내 결과 스크롤, 배경 스크롤 잠금, Tab 순환 및 닫은 후 포커스 복구를 제공한다.
5. **검증**: 프로덕션 빌드, 실제 생성된 전체 HTML의 좁은/넓은 화면 넘침 검사, 대표 라우트별 주요 화면 및 경계 크기 검사, 검색·테마·페이지 이동·카테고리·목차 키보드/터치 조작, 긴 문자열/코드/표 스트레스 검사를 수행한다. 변경 전후 스크린샷과 결과를 PR에 포함한다.

## 화면 규칙과 수용 기준

- PC: 1440×900, 1920×1080. 사이드바/본문/목차가 겹치지 않는다.
- 태블릿: 768×1024, 1024×768. 카테고리 접근성과 목록 가독성을 유지한다.
- 모바일: 320×740, 375×812, 390×844. 문서 전체 가로 스크롤 없이 카드·본문·검색을 사용할 수 있다.
- 경계: 600/601, 680/681, 980/981, 1180/1181px.
- 모든 화면에서 키보드 포커스를 확인하고 검색 결과·코드·표의 내부 스크롤은 허용한다.
- 실제 iOS/Android, 소프트 키보드 및 외부 giscus 서비스 자체 동작은 로컬 Chromium 검증과 구분해 한계를 기록한다.
